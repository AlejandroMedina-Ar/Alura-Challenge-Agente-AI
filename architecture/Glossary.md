# Glossary and Naming Conventions

**Version:** 1.0

**Status:** Reference

---

# Purpose

This document defines canonical terminology and naming conventions used throughout the TechFlow AI Corporate Knowledge Agent project.

Use this glossary to resolve naming conflicts and ensure consistency across all documentation and code.

---

# Core Terminology

## Knowledge Asset

**Definition:** The formal/technical term for any document uploaded to the system.

**Usage:** 
- Technical documentation
- Code comments
- Architecture discussions
- Specifications

**Examples:**
- "The administrator uploaded 3 knowledge assets."
- "Each knowledge asset is assigned a unique asset_id."

---

## Document

**Definition:** The informal/user-facing term for knowledge assets.

**Usage:**
- User interface
- Error messages
- Help text
- User-facing notifications

**Examples:**
- "Upload documents to the Knowledge Library."
- "3 documents processed successfully."

**Relationship:** Document is the user-friendly synonym for Knowledge Asset.

---

## Knowledge Base

**Definition:** The complete system including Knowledge Library, metadata, embeddings, and vector database.

**Usage:** High-level architectural discussions.

**Components:**
- Knowledge Library (uploaded files)
- Metadata (asset information)
- Chunks (processed text segments)
- Embeddings (vector representations)
- Vector Database (ChromaDB)

---

## Knowledge Library

**Definition:** The administrator-managed collection of knowledge assets stored in `data/knowledge_library/`.

**Usage:** When referring specifically to the file storage system.

**Not to be confused with:** Knowledge Base (which includes embeddings and vector storage).

---

## Session State

**Definition:** Temporary in-memory conversation context during the current active session using Streamlit session state.

**Scope:** Current chat only, cleared on browser refresh.

**Usage:** Technical discussions about conversation memory.

**Examples:**
- "Session state stores the current conversation."
- "Session state is not persisted across sessions."

---

## Conversation History (Persistent)

**Definition:** Saved chat conversations across sessions (stored in database or filesystem).

**Status in v1:** Explicitly OUT OF SCOPE.

**Usage:** When discussing future features or clarifying what v1 does NOT include.

---

## Chunk

**Definition:** A segment of text extracted from a knowledge asset, sized for optimal retrieval (default: 1000 characters with 200 character overlap).

**Technical details:**
- Has unique chunk_id (UUID)
- References parent asset_id
- Stores metadata (page number, language, source)
- Generates one embedding vector

---

## Embedding

**Definition:** A vector representation of text generated by an embedding model (default: intfloat/multilingual-e5-base).

**Purpose:** Enable semantic similarity search in ChromaDB.

---

## RAG (Retrieval-Augmented Generation)

**Definition:** The workflow of retrieving relevant context from the Knowledge Base before generating an LLM response.

**Workflow:**
1. Generate query embedding
2. Retrieve relevant chunks
3. Build prompt with context
4. Generate answer via LLM

---

# Version Terminology

**Standard format:** v1 (lowercase 'v', no space)

**Alternatives to avoid:**
- ~~Version 1~~
- ~~Version 1.0~~
- ~~V1~~

**Usage:** "This feature is out of scope for v1."

## Fallback Provider

# File and Module Naming Conventions

## Python Files

**Format:** `snake_case.py`

**Examples:**
- `authentication_service.py` ✓
- `knowledge_library_service.py` ✓
- `embedding_service.py` ✓

**Avoid:**
- ~~`authService.py`~~ (camelCase)
- ~~`auth-service.py`~~ (kebab-case)

---

## Service Modules

**Pattern:** `<domain>_service.py`

**Examples:**
- `chat_service.py`
- `authentication_service.py`
- `knowledge_library_service.py`
- `configuration_service.py`
- `indexing_service.py`

**Not:** ~~`auth_service.py`~~ (use full name: `authentication_service.py`)

---

## Classes

**Format:** PascalCase

**Examples:**
- `ChatService`
- `AuthenticationService`
- `KnowledgeLibraryService`
- `RAGPipeline`
- `VectorStore`

---

## Constants

**Format:** SCREAMING_SNAKE_CASE

**Examples:**
- `MAX_CONTEXT_CHUNKS`
- `CHUNK_SIZE`
- `DEFAULT_TEMPERATURE`
- `EMBEDDING_MODEL`

---

## Variables and Functions

**Format:** snake_case

**Examples:**
- `generate_embeddings()`
- `retrieve_context()`
- `build_prompt()`
- `asset_id`
- `chunk_count`

---

# Directory Naming

**Format:** lowercase, no spaces

**Examples:**
- `src/`
- `knowledge_library/`
- `chromadb/`
- `assets/`

**Avoid:** CamelCase or spaces in directory names.

---

# Configuration Variables

## Environment Variables (`.env`)

**Format:** SCREAMING_SNAKE_CASE

**Examples:**
- `ADMIN_PASSWORD`
- `GEMINI_API_KEY`
- `COHERE_API_KEY`
- `EMBEDDING_MODEL`
- `CHUNK_SIZE`

---

## Runtime Configuration (`config.json`)

**Format:** snake_case (JSON keys)

**Examples:**
```json
{
  "theme": "tokyo_night",
  "max_context_chunks": 4,
  "temperature": 0.2
}
```

# Repository Structure Terms

## Source Code

**Location:** `src/`

**Contains:** All Python application code.

---

## Runtime Data

**Location:** `data/`

**Contains:** Knowledge Library, ChromaDB, logs, config.json.

**Important:** This directory is created at runtime and should NOT be committed to Git.

---

**Location:** `assets/`

# Usage Guidelines

## When writing specifications:
- Use "Knowledge Asset" in technical sections
- Use "Document" when describing user interactions
- Use "v1" for version references
- Use "Tokyo Night" for the default theme

## When writing code:
- Follow snake_case for files, variables, functions
- Follow PascalCase for classes
- Follow SCREAMING_SNAKE_CASE for constants
- Use descriptive names (e.g., `authentication_service.py`, not `auth_service.py`)

## When writing user-facing text:
- Use "document" instead of "knowledge asset"
- Use "upload documents" instead of "upload knowledge assets"
- Use simple, friendly language

# Conflict Resolution

If two documents use different terms for the same concept:

1. Check this Glossary for the canonical term
2. Update the inconsistent document
3. Use the canonical term going forward

If a term is not in this Glossary but appears in multiple documents with different meanings:

1. Add it to this Glossary with a clear definition
2. Update all affected documents to use the canonical definition
